# Видеопоток симулятора: кодирование и декодирование (VideoToolbox)

`swift run -c release vtbench [--fps 60] [--seconds 10] [--no-llrc] [--json out.json]`

Кадры синтетические, похожие на UI (прокручивающийся список с текстом). Кадры подаются в реальном
времени с заданной частотой, первая секунда (прогрев) в замер не входит. «Итого» — от подачи кадра
в кодер до получения декодированного кадра, без сети, захвата и отрисовки.

## Хост: Apple M4, macOS 27.0.1, аппаратные кодеры H.264/HEVC есть

60 fps, low-latency rate control (режим для видеозвонков):

| Кодек | Размер | Кодирование p50/p95, мс | Декодирование p50, мс | Итого p50/p95, мс | Мбит/с |
|---|---|---|---|---|---|
| H.264 | 1206×2622 | 10.2 / 11.7 | 3.3 | 13.6 / 15.7 | 1.0 |
| H.264 | 603×1311 | 7.9 / 8.6 | 2.6 | 10.6 / 11.6 | 0.7 |
| HEVC | 1206×2622 | 10.7 / 12.0 | 3.3 | 14.2 / 16.3 | 0.9 |
| HEVC | 603×1311 | 8.3 / 9.1 | 2.5 | 10.9 / 12.0 | 0.6 |

Обычный rate control: полное разрешение медленнее (итого около 22 мс), половинное быстрее
(около 8 мс), но битрейт в 2–3 раза выше. 120 fps на полном разрешении не тянет (кадры теряются),
на половинном держит около 9.5 мс.

**Вывод для хоста:** кодирование и декодирование вместе укладываются в 10–15 мс, то есть меньше
одного кадра на 60 fps. Поток 1–2 Мбит/с, upload домашнего интернета не будет узким местом.
Разумная настройка по умолчанию: H.264 (декодируется везде, включая браузер и VS Code webview),
половинное разрешение, 60 fps, low-latency rate control.

## macOS-гость (Virtualization.framework)

Не измерено: нужна VM. Это главный открытый вопрос. Если в госте нет аппаратного кодера
(строка `hardware encoders: none` в выводе), кодировать придётся на хосте, а кадры передавать
из гостя по vsock.
