# macOS-гость: что работает внутри VM

## Условия

- Хост: Apple M4, 16 ГБ, macOS 27.0.1. Образы VM лежат на внешнем USB SSD (Samsung 870 EVO, ~250 МБ/с).
- Гость: macOS 27.0 (26A428), 4 CPU, 8 ГБ. Базовый образ `ghcr.io/cirruslabs/macos-golden-gate-vanilla:27.0`, в нём установлены Xcode 27.2 и рантайм iOS 27.2 (см. `images/README.md`).
- VM поднимает `agent/…/maccheri-vm` тем же кодом, что и агент: клон образа через `clonefile`,
  Virtualization.framework, NAT, virtiofs-шара.

## Результаты

| Проверка | Результат |
|---|---|
| От старта VM до адреса по DHCP | 12–22 с |
| SSH, общая папка `/Volumes/My Shared Files` | работают |
| Metal | `Apple Paravirtual device`: GPU-семейства Apple7/Apple9 не заявлены, рабочий набор 5,7 ГБ |
| Аппаратные видеокодеры | есть, паравиртуальные: H.264, HEVC, ProRes |
| Загрузка симулятора iOS 27.2 | первая — ~50 с, повторная — ~15 с |
| Клон удаляется после выключения гостя | да |

### Кодирование видео (`bench/stream` → vtbench, 60 fps, low-latency rate control)

| Кодек | Размер | Гость: итого p50/p95, мс | Хост: итого p50/p95, мс |
|---|---|---|---|
| H.264 | 603×1311 | 7.4 / 8.8 | 10.6 / 11.6 |
| HEVC | 603×1311 | 10.7 / 12.8 | 10.9 / 12.0 |
| H.264 | 1206×2622 | 15.0 / 39.4, кадры теряются | 13.6 / 15.7 |

### Касание → изменённый кадр в симуляторе (`bench/simlatency`, 100 касаний)

| Где | p50, мс | p95, мс |
|---|---|---|
| Хост | 7.9–8.0 | 9.7–10.6 |
| Гость, система успокоилась | 4.5–4.7 | 8.6–12.8 |
| Гость, сразу после загрузки | 5.8–7.0 | 22–152 |

## Выводы

- Симулятор iOS внутри VM работает, задержка не хуже, чем на хосте.
- Видео можно кодировать в госте аппаратно. Передавать кадры на хост не нужно.
- Первые несколько минут после загрузки фоновые службы гостя дают большие хвосты задержки.
  Часть этого — чтение образа рантайма с медленного USB-диска. Для интерактивных сессий
  гостя стоит прогревать заранее или держать в пуле уже загруженных VM.
- Первый запуск `simlatency` после загрузки симулятора иногда не получает кадров. Повторный
  запуск работает.
