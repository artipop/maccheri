# Продукт: идея, сегменты, рынок, риски

Собрано из обсуждений 2026-10-16…21. Решения с датами — в `decisions.md`, угрозы — в `threat-model.md`,
сеть — в `networking.md`, удалённый симулятор — в `remote-simulator.md`, план работ — в `roadmap.md`.

## Идея

Владельцы маков сдают простаивающие машины под чужие задачи. Каждая задача идёт в одноразовой macOS-VM
(Virtualization.framework), после неё VM удаляется. Ниша реальная: macOS CI стоит в разы дороже Linux, а маки
на Apple Silicon по ночам простаивают миллионами. По сути — «Vast.ai для маков».

## Какую нагрузку можно отдавать чужому железу

Безопасно, когда выполнены три условия:
1. **Данные не секретны** или секреты можно вынести из задачи.
2. **Результат дёшево проверить**, или ошибка не страшна.
3. **Падение ноды не критично**: задачу можно просто перезапустить.

| | Данные | Проверка результата | Падение ноды |
|---|---|---|---|
| Edge / серверы | ❌ трафик пользователей, данные третьих лиц | ❌ каждый ответ (хост может подменить ответ) | ❌ нужен failover |
| Релизные iOS-сборки | ⚠️ код | ⚠️ хост может внедрить бэкдор в бинарь | ✅ |
| **CI-проверки (тесты, линт, PR-сборки, UI-тесты)** | ⚠️ код / ✅ для open source | ✅ худшее — ложный «зелёный», ловится выборочным дублированием | ✅ |
| **Интерактивный симулятор** | ⚠️ хост видит загруженный `.app` | ✅ человек видит результат | ⚠️ сессия обрывается |
| Обучение моделей | ❌ / ✅ только открытые датасеты | ❌ дорого, веса можно отравить | ⚠️ часы и дни, нужны чекпоинты |
| Вычисления на публичных данных | ✅ | ⚠️ дублированием | ✅ |

Выводы:
- **Edge и серверы не делаем.** Утечка трафика третьих лиц и подмена ответов не решаются без аппаратного TEE,
  а у домашних маков нет преимущества перед Cloudflare, Fly и Hetzner.
- **Ядро — macOS/iOS CI-проверки и удалённый симулятор.** Артефакт никуда не уходит, а падение ноды не критично.
- **Релизные сборки** — позже и только с подписью на доверенной стороне и двойной сборкой.
- **Обучение и MLX** — возможное второе направление на том же агенте, только на открытых данных.
  Единственное реальное преимущество мака — общая память для LoRA больших моделей. Замер: `bench/mlx/RESULTS.md`.

## Сегменты

- **A. Open source.** Утекать нечему, старт быстрый, платят мало, зато это хороший маркетинговый канал.
- **B. Private pool.** Компания или команда объединяет свои маки (офисные Mac mini, машины сотрудников)
  в собственный CI- и симуляторный кластер. Это снимает сразу несколько проблем:
  - доверие решается организационно;
  - лицензионный вопрос сильно проще;
  - не нужны выплаты физлицам;
  - понятно, кто платит.
- **C. Публичный маркетплейс для закрытого кода.** Самый большой рынок и самый большой риск: лицензия,
  доверие, выплаты.

**Текущий фокус (M1):** свои и команда, то есть B. Оба трека, CI и симулятор, идут на одной технологии.
Публичный маркетплейс — только после юридического разбора (см. «Лицензия Apple»).

## Лицензия Apple (проверить у юриста)

По памяти из macOS SLA:
- Виртуализация macOS разрешена только на железе Apple, **не больше 2 macOS-VM на один мак**.
  Ограничение зашито в ядро.
- Виртуализация разрешена для разработки, тестирования и серверного использования.
- **Сдавать мак в аренду можно одному арендатору в эксклюзивное пользование минимум на 24 часа подряд.**
  Поэтому у AWS EC2 Mac минимальная аренда — сутки.
- Xcode распространять нельзя. Образы с Xcode для чужих владельцев, скорее всего, придётся собирать
  у них на месте, из их Apple ID.

Следствие: поминутная продажа кусков чужих маков посторонним людям противоречит лицензии. Возможные модели:
- self-hosted пулы как SaaS: «свои маки для своих команд»;
- аренда целой машины на сутки и дольше (это хорошо ложится на интерактивные сессии и обучение);
- B2B-договоры.

**Это главный риск идеи. Решать до вложений в маркетплейс.** Linux-гостей ограничения не касаются.

## Конкуренты

**CI для macOS/iOS:** GitHub Actions (macOS-раннеры), Xcode Cloud, Bitrise, Codemagic, Cirrus CI, MacStadium,
AWS EC2 Mac, Scaleway Apple silicon.

**Удалённый симулятор и устройства:** Appetize.io, BrowserStack. Смежные инструменты: SimDeck (open source,
симулятор по WebRTC в браузер и в редакторы), Radon IDE (симулятор в VS Code, только локальный мак),
Remote iOS Simulator от Microsoft (только Visual Studio под Windows), idb от Meta. Подробнее — в `remote-simulator.md`.

**Наше преимущество** — цена за счёт простаивающих маков. **Слабые места** — надёжность домашних маков
и доверие к хосту. Из-за правила 24 часов ценовое преимущество работает в основном для команд со своими
маками, а не для публичной поминутной продажи.

## Экономика (открытые вопросы)

- Сколько реально зарабатывает хост. Если $10–20 в месяц за мак, мотивации мало. Нужно считать.
- Выплаты хостам по всему миру — отдельная боль: Stripe Connect, налоги, KYC.
- Для private pool модель проще: подписка за пул или за мак.
- Наши расходы: control plane на маленьком VPS, TURN-трафик для 10–20% сессий симулятора, которые
  не пробивают NAT.

## Что ещё нужно продукту (честный список, 2026-10-21)

**До любого публичного запуска**
- Юридический разбор лицензии Apple: правило 24 часов, Xcode.
- Модель доверия к хосту (см. `threat-model.md`): проверенные хосты, договоры, задачи без секретов.

**Для CI**
- **Кэши между задачами:** SPM, DerivedData, CocoaPods. Одноразовая VM каждый раз собирает с нуля, и без кэша
  мы проигрываем GitHub-раннерам по скорости. Самое заметное для пользователя.
- Артефакты и логи, повторы упавших задач, раннеры на уровне организации GitHub.
- Подпись релизных сборок только на доверенной стороне.

**Для симулятора**
- Логи и консоль приложения, скриншоты и запись экрана, геолокация, push, deep links.
- Сохранение состояния симулятора между сессиями, выбор устройств, iPad.
- Трафик приложения в симуляторе через машину разработчика: доступ к его `localhost` и dev-серверу
  (см. `networking.md`).
- Позже: удалённая отладка (lldb), это сложно.

**Хосты и образы**
- Раздача образов (30–90 ГБ) и обновления по разнице: Xcode выходит раз в несколько недель.
- Надёжность домашних маков: сон, офлайн, слабый upload (у тестового мака ~2 МБ/с), учёт качества хоста.
- Автообновление агента (Sparkle), подпись Developer ID и нотаризация.

**Платформа**
- Аккаунты: вход через GitHub, команды, квоты, защита от злоупотреблений (майнинг в CI).
- Наблюдаемость: логи и метрики сервера и агентов, отчёты о падениях, алерты.
- Бэкапы, а позже отказоустойчивость control plane.
- Если будет маркетплейс: оплата, выплаты, налоги, KYC.
