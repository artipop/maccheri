# Удалённый симулятор iOS

Разработчик работает в браузере с симулятором, который запущен в macOS-VM на чужом маке. Задержка
«нажал — увидел» должна быть такой, чтобы ощущалось как локально (ориентир — меньше 100 мс).

## Что есть на рынке (2026-10)

- **SimDeck** (Apache-2.0): CLI и демон на маке, передаёт картинку iOS-симулятора по WebRTC в браузер,
  VS Code, Cursor, Claude Code, на другой мак или iPad. Умеет тапы и ввод текста. https://simdeck.sh/
- **Radon IDE** (Software Mansion): симулятор внутри VS Code. Серверная часть закрыта, работает только
  на локальном маке.
- **Remote iOS Simulator** от Microsoft: только Visual Studio 2022 под Windows, не VS Code.
- **idb** от Meta: поток H.264 с симулятора и инъекция нажатий. Сжатие и доставку делаешь сам.
- **Appetize.io, BrowserStack:** коммерческие облачные симуляторы и устройства.

Все берут кадры и подают нажатия через приватные API CoreSimulator и SimulatorKit. Нам это подходит: версию
Xcode в образе выбираем мы.

## Как устроено у нас (M1)

```
браузер ──WebRTC P2P (TURN при неудаче)──▶ HostPeer в агенте (хост) ──TCP через NAT агента──▶ simstream (гость :7300) ──▶ симулятор
        ◀── сигнализация через control plane (WebSocket) ──▶
```

- **Захват** (`simstream/Sources/SimulatorBridge`): колбэки `SimDeviceScreen`, кадры из IOSurface приходят
  только при изменениях, в простое трафика нет.
- **Касания:** `SimDeviceLegacyHIDClient` и `IndigoHIDMessageForMouseNSEvent`. В Xcode 27 у функции
  шесть аргументов: последний — CGSize экрана в d0/d1. С сигнатурой из idb касания молча теряются.
- **Кодирование:** H.264 через VideoToolbox (low-latency rate control, RealTime, без переупорядочивания кадров)
  прямо в госте: аппаратный кодер там паравиртуальный.
- **Транспорт:** libdatachannel на хосте. Видео идёт либо RTP-дорожкой, либо через канал данных
  с декодированием WebCodecs в браузере. Режим переключается на лету, по умолчанию дорожка.
  Как выбирать режим, решим по замерам через интернет.
- **Клиент:** веб-приложение на TypeScript (`web/`), раздаётся с control plane. Mac Viewer (`viewer/`) — для замеров.
- **Возможности:** клавиатура, Home, блокировка, поворот, установка `.app` перетаскиванием.

## Как это влияет на архитектуру

- **Другой тип сессии:** интерактивная аренда на часы, а не «задача — и уничтожить VM». Это лучше ложится
  на лицензионное правило Apple «один арендатор от 24 часов», чем поминутный CI.
- **Планирование** должно учитывать географию (RTT), upload хоста (2–5 Мбит/с на поток) и RAM: Xcode
  и симулятор в госте занимают около 8 ГБ, на маке с 16 ГБ помещается одна VM.
- **Прогретые VM обязательны.** В первые минуты после загрузки гостя хвосты задержки доходят до 150 мс,
  а холодный старт приложения иногда даёт чёрный экран на 1–3,5 с. Пул агента держит прогретого гостя:
  сессия готова через 7–13 с.
- **Доверие:** хост видит `.app` (см. `threat-model.md`).

## Открытые вопросы

- Замеры через интернет: дорожка против канала данных, разные браузеры, потери, TURN.
- Трафик приложения через машину разработчика (см. `networking.md`).
- Хрупкость приватных API при обновлениях Xcode: нужен регресс-тест на каждую новую версию.
- Встраивание в VS Code (webview) и нативная обёртка (кандидат — Wails 3, см. `roadmap.md`).
