# Roadmap: от прототипа к продукту

Состояние на 2026-10-21.

## Что работает

- VM: агент клонирует базовый образ `macos-27-xcode-27.2`, поднимает его через Virtualization.framework
  и удаляет клон после выключения гостя (`maccheri-vm`, `images/README.md`).
- Внутри гостя работают Xcode, симулятор iOS, Metal и аппаратные видеокодеры (`bench/vm/RESULTS.md`).
- Удалённый симулятор: `simstream` в госте, проброс порта на хосте, Maccheri Viewer на другом маке.
  Задержка клик → кадр 22–26 мс p50 в локальной сети (`bench/simstream/RESULTS.md`).
- Control plane (Vapor) и агент для CI-заданий GitHub существуют в виде каркаса с тестами. Сквозной прогон
  через GitHub ещё не делали.

## Решения

- Первые пользователи — свои и команда. Пул приватный, доступ через интернет. Публичный маркетплейс,
  оплата и модерация будут позже.
- Треки «удалённый симулятор» и «CI (GitHub runners)» идут параллельно, общие части делаем один раз.
- Основной клиент удалённого симулятора — **браузер** (TypeScript, `web/`), потому что многие клиенты
  сидят на Linux и Windows. Mac Viewer (SwiftUI) остаётся инструментом разработки и замеров.
  Встраивание в VS Code (webview) и нативные обёртки (Tauri) — позже, поверх того же веб-клиента.
- Подпись Developer ID и нотаризация — в последнюю очередь. До этого подпись ad-hoc, а при установке
  на другой мак нужен `xattr -dr com.apple.quarantine`.
- Связь клиента с хостом через интернет **пока не решена**. Склоняемся к WebRTC: P2P, наш
  сервер только для сигнализации и запасной ретранслятор (TURN). Вопрос: нужен ли дополнительно
  P2P VPN (WireGuard) для произвольного доступа к гостю. CI туннель не нужен: раннер сам ходит в GitHub.

## Открытые вопросы

- Где развернуть control plane: нужен публичный HTTPS для вебхуков GitHub и сигнализации. Есть ли домен?
- Транспорт: только WebRTC или WebRTC плюс P2P VPN.
- Образы для внешних владельцев: лицензия Xcode запрещает его распространять. Для своих не проблема.

## Работы

### Общие

1. **Maccheri.app (хост).** Приложение в строке меню, внутри агент:
   - пул VM с одной прогретой машиной;
   - изоляция гостя от локальной сети владельца, доступ только в интернет;
   - настройки CPU, RAM и расписания доступности, автозапуск.
2. **Control plane:**
   - команда: инвайты и токены;
   - регистрация хостов, heartbeat;
   - выдача сессий симулятора и CI-заданий, сигнализация для P2P;
   - деплой.
3. **Образ.** Автоматическая сборка по рецепту, в образе сразу GitHub runner и simstream как служба гостя.

### Трек «Симулятор»

4. Транспорт через интернет (см. «Решения»), шифрование, токен сессии.
5. Загрузка своего `.app` в симулятор, клавиатура, поворот экрана, Home, выбор устройства.
6. Веб-клиент: вход, список доступных маков и устройств, подключение через control plane, WebRTC в браузере.

### Трек «CI»

7. GitHub App на аккаунте владельца проекта, раннер в образе, сквозной прогон «push → задание в нашей VM».

### Последним

8. Подпись Developer ID, нотаризация, обновления (Sparkle) для Maccheri.app.
