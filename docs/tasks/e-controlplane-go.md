# E: control plane на Go

Сначала прочитай `docs/contracts.md` (общие правила, владельцы папок), `docs/decisions.md` и `controlplane/DESIGN.md`.
Твои папки: `controlplane-go/` (новая), а на последнем шаге — `deploy/` и удаление `controlplane/`.
Worktree: `../maccheri-e`, ветка `task/controlplane-go`.

## Цель

Переписать control plane с Vapor на Go **без изменения поведения для клиентов**, то есть для агента, Maccheri.app,
веб-клиента и simstream-peer. Заодно встроить TURN-сервер (pion/turn) вместо отдельного coturn. Когда Go-версия
пройдёт приёмку, она заменит Vapor-версию в `deploy/`, а `controlplane/` удаляется.

Почему: лёгкий деплой (один статический бинарь, сборка за секунды даже на маленьком VPS), TURN в нашем коде
(учётки, лимиты, статистика ретрансляции), серверная экосистема Go для GitHub, WebRTC и VPN, общий язык
с будущей обёрткой на Wails 3. Подробнее — `docs/decisions.md`, `docs/networking.md`.

## Источник правды для поведения

1. **JSON-фикстуры** `controlplane/Tests/Fixtures/*.json`: 30 примеров всех запросов и ответов. Go-сервер
   обязан **принимать и отдавать ровно такой JSON**. Нюансы кодирования Swift `Codable`, которые нужно повторить:
   - UUID в верхнем регистре;
   - поля со значением nil отсутствуют, а не равны `null`;
   - перечисления с данными: `{"ci":{"_0":{…}}}`, `{"offer":{"sdp":"…"}}`, `{"bye":{}}`;
   - даты в ISO 8601 так же, как в фикстурах (проверь, есть ли дробные секунды);
   - TURN-учётка в `session-ready.json` — настоящий тестовый вектор с секретом `fixture-turn-secret`.
2. **`controlplane/DESIGN.md`:** таблицы, машина состояний сессии, подбор хоста, фоновая проверка, сигнализация
   (коды до апгрейда 403/404/409/410, вытеснение сокета той же роли кодом 4000, очередь 256 кадров по 64 КБ,
   ping каждые 20 с), TURN REST, env.
3. **Документация типов в `protocol/Sources/MaccheriProtocol/*.swift`:** пути, коды ответов, семантика ёмкости,
   `endedSessions`, 410 на отчёт о состоянии.
4. **Тесты Vapor** (`controlplane/Tests/ControlPlaneTests`, 37 штук) — список сценариев, которые надо перенести.

Если находишь расхождение между этими источниками или неочевидное поведение, не выбирай молча: напиши
координатору.

## Стек (рекомендация, отступать можно с обоснованием в README)

- Go последней стабильной версии, `net/http` с шаблонами маршрутов из stdlib, `log/slog`.
- SQLite через `modernc.org/sqlite` (чистый Go, без cgo, чтобы бинарь был статическим). Схема — та же,
  что в `DESIGN.md`. Будет плюсом, если Go-версия откроет файл БД Vapor-версии; если нет, опиши, как перейти.
- WebSocket: `github.com/coder/websocket`.
- GitHub App: JWT RS256 (`golang-jwt`) и HTTP-клиент; можно `ghinstallation` и `go-github`.
  Проверка подписи вебхука — HMAC-SHA256, сравнение за постоянное время.
- **TURN: `github.com/pion/turn/v4`, встроенный в тот же процесс:**
  - UDP и TCP 3478, диапазон relay-портов `TURN_MIN_PORT`–`TURN_MAX_PORT`, `TURN_EXTERNAL_IP` для 1:1 NAT;
  - TURN поверх TLS на 443: Caddy (layer4 по SNI `TURN_DOMAIN`) проксирует TCP в наш TLS-листенер
    или в TCP-листенер с PROXY protocol. Схему выбери и опиши;
  - аутентификация — та же TURN REST (`username = "<expiry>:<session id>"`, HMAC-SHA1 от `TURN_SECRET`),
    чтобы клиенты не менялись. Проверка срока и того, что сессия жива;
  - запрет relay в приватные диапазоны (RFC 1918, loopback, link-local, CGNAT, адреса самого сервера),
    как сейчас в конфиге coturn;
  - счётчики: число аллокаций и байты на сессию, в лог при завершении сессии.
- Docker: многоэтапная сборка, итоговый образ `distroless/static` или `scratch` + CA-сертификаты,
  `web/dist` внутри, как сейчас (`npm ci && npm run build`, если есть `web/package.json`).

## Что сделать

1. **Типы и фикстуры.** Go-типы для всех контрактов. Тест: каждая фикстура декодируется и кодируется обратно
   в эквивалентный JSON (сравнение по смыслу, а не по байтам), а ответы обработчиков совпадают с фикстурами.
2. **Всё, что умеет Vapor-версия:**
   - доступ: `MACCHERI_SHARED_TOKEN` на `/v1/*`, `agentToken` на `/agent/v1/*`, инвайты и токены
     пользователей, `ADMIN_INVITE`, команда `create-invite --admin`;
   - хосты: enroll, heartbeat, `HeartbeatResponse.endedSessions`, офлайн по таймауту, `GET /v1/hosts`;
   - long-poll `/agent/v1/work` (25 с, сначала симулятор с предпочтением прогретых хостов, потом CI),
     отчёты о состоянии (410 Gone для завершённых), `complete` для CI;
   - сессии: машина состояний, истечение, таймауты очереди и старта, офлайн хоста, лимит на пользователя;
   - сигнализация по `DESIGN.md`, токены не попадают в логи;
   - GitHub: вебхук `workflow_job`, очередь CI в БД, jitconfig на уровне репозитория;
   - раздача `web/dist` с SPA-fallback, `/healthz`;
   - env — те же имена (таблица в `DESIGN.md`) плюс TURN-переменные из `deploy/.env.example`.
     `deploy/.env` не должен меняться, кроме удаления того, что было нужно только coturn.
3. **Перенос тестов.** Все сценарии тестов Vapor, плюс TURN: аллокация с правильной учёткой, отказ
   с неправильной или просроченной, отказ relay в приватный адрес.
4. **Локальная проверка.** `deploy/compose.local.yml` с Go-версией вместо Vapor (можно отдельный файл
   на время сравнения). Проверь `/healthz` и TURN через `deploy/turn-check.sh` или `turnutils_uclient`.
5. **Сквозная приёмка** (проводит координатор, ты готовишь стенд):
   - браузер со второго мака → Go control plane → `maccheri-agent` → VM → симулятор, прямое соединение;
   - то же с `?relay=1`: соединение через встроенный TURN;
   - CI: подписанный тестовый вебхук → задание → агент → VM (с фиктивным jitconfig), а когда будет GitHub App, —
     настоящий workflow.
6. **Подмена** (после приёмки и с согласия координатора):
   - `deploy/`: сервис `controlplane` собирается из `controlplane-go`, coturn удалён, Caddy/layer4 и порты
     в README обновлены, `.env.example` почищен;
   - `controlplane/` (Vapor) удалить, фикстуры перенести в `controlplane-go/testdata/`, `DESIGN.md` — туда же;
   - README и `docs/contracts.md`: обновить строки про control plane (правки в `docs/` — через координатора).

## Готово, когда

- `go test ./...` зелёный: фикстуры, все перенесённые сценарии, TURN.
- Сквозная приёмка пройдена в обоих режимах (прямое соединение и TURN), CI — хотя бы с подписанным
  тестовым вебхуком.
- Docker-образ собирается на Linux за минуты и весит десятки мегабайт, а не сотни.
- `deploy/` работает на Go-версии, Vapor удалён, документация обновлена.

## Не делать

Новые функции (аккаунты через GitHub, кэши CI, биллинг) — только перенос и TURN. Не менять контракт:
если без этого никак, предложи координатору. Не трогать `agent/`, `hostapp/`, `guest/`, `simstream/`, `web/`.
