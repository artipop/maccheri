# M1 / A: Maccheri.app, агент и пул VM

Сначала прочитай `docs/contracts.md` (общие правила, владельцы папок, блокировка VM) и `docs/roadmap.md`.
Твои папки: `hostapp/`, `agent/`. Worktree: `../maccheri-a`, ветка `task/host`.

## Цель

Владелец мака ставит Maccheri.app, вводит адрес control plane и свой токен, после чего мак сам
подключается к пулу команды: берёт CI-задания и сессии симулятора, держит прогретую VM, изолирует
гостя от домашней сети и показывает, что сейчас происходит.

## Что есть

- `agent/`: `AgentCore` (ImageStore с clonefile, VirtualizationRunner, JobRunner для CI),
  CLI `maccheri-agent` (CI через `/agent/v1/lease`), `maccheri-vm` (ручной запуск, `--forward`, `--attach`),
  `TCPForwarder`.
- `hostapp/`: каркас приложения в строке меню (JSON `project.xcproj`), пока без логики.
- Замеры: гость получает адрес по DHCP через 12–22 с после старта. В первые минуты после загрузки
  у гостя большие хвосты задержки, поэтому для симулятора нужна прогретая VM (`bench/vm/RESULTS.md`).

## Что сделать

1. **Агент на новом API** (`Work.swift`, `Hosts.swift`):
   - регистрация через `POST /v1/hosts/enroll` с токеном пользователя, токен агента хранится в Keychain;
   - heartbeat каждые `HostAPI.heartbeatIntervalSeconds` с `HostCapacity`
     (образы и `maccheri.json` от C, слоты, прогретые VM);
   - long-poll `/agent/v1/work` и диспетчеризация `WorkLease.ci` / `.simulator`;
   - для CI записать `session.json` (`GuestSession.ci`), загрузить VM, дождаться, пока она выключится,
     отправить `complete`;
   - для симулятора взять прогретую VM или поднять новую, записать `GuestSession.simulator`,
     отправить отчёт `starting`, дождаться, пока гость начнёт принимать соединения на `:7300`,
     отправить `ready`, запустить `HostPeer` от D (до её готовности — заглушку), по завершении
     погасить VM и отправить `ended`;
   - таймауты (`timeoutSeconds`) и гарантированная очистка клонов, в том числе после падения агента:
     при старте удалять осиротевшие каталоги в `work/`.
2. **Пул VM:**
   - N прогретых гостей (по умолчанию 1), уже загруженных, с пустой общей папкой;
   - лимиты: не больше 2 VM (лицензия Apple), по RAM — с учётом памяти хоста и настроек;
   - при исчерпании ресурсов — честная ёмкость в heartbeat.
3. **Сеть гостя.** Гость не должен видеть локальную сеть владельца (RFC 1918, link-local, сам хост),
   только интернет. Варианты:
   - `VZFileHandleNetworkDeviceAttachment` и свой NAT в пространстве пользователя, без root;
   - правила pf через привилегированный helper (SMAppService);
   - что-то ещё.

   Выбери, обоснуй коротко в `agent/README.md` и проверь из гостя: `curl` в интернет работает,
   `ping 192.168.x.1` и доступ к хосту — нет. Агенту при этом нужно соединяться с гостем на `:7300`
   (стык с D, `connectToGuest`) — сохрани это или замени vsock.
4. **Maccheri.app:**
   - строка меню: статус (онлайн/офлайн, текущие сессии и задания, прогретые VM), пауза и возобновление;
   - настройки: адрес control plane, вход (токен), каталоги образов и клонов, сколько VM, CPU и RAM,
     автозапуск (SMAppService);
   - агент работает внутри приложения: VZ нужен главный run loop, а у приложения он есть.
     CLI `maccheri-agent` остаётся для работы без интерфейса.
5. Тесты на диспетчеризацию, пул и очистку, с фейковым `VMRunner` и фейковым сервером. Сквозная
   проверка с локально запущенным control plane B или с фейковым, если B ещё не готов.

## Готово, когда

- Приложение на этом маке регистрируется в control plane, держит одну прогретую VM и отрабатывает
  сессию симулятора (с заглушкой или настоящим HostPeer) и CI-задание (с C) от начала до конца,
  после чего в `work/` пусто.
- Гость не видит локальную сеть.
- `swift test` в `agent/` зелёный, приложение собирается через `xcodebuild`.

## Не делать

Подпись Developer ID и нотаризацию, автообновления, загрузку образов из сети (образы кладёт C).
