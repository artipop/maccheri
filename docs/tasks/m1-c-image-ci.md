# M1 / C: базовый образ, служба в госте, сквозной CI

Сначала прочитай `docs/contracts.md` (общие правила, владельцы папок, блокировка VM) и `docs/roadmap.md`.
Твои папки: `images/`, `guest/`. Worktree: `../maccheri-c`, ветка `task/image`.

## Цель

Воспроизводимая сборка базового образа одной командой. В образе служба гостя, которая делает ровно
одно дело из `session.json`: выполняет CI-задание или обслуживает сессию симулятора. Плюс сквозной
прогон CI через GitHub.

## Что есть

- Рецепт образа, выполнявшийся руками: `images/README.md`. Tart (`~/.local/bin/tart`,
  `TART_HOME=/Volumes/Dev/vm/tart`), vanilla-образ macOS 27, Xcode и рантайм iOS переносятся с хоста
  через tar и dmg, подробности там же.
- `guest/runner/`: скрипт и plist для однократного запуска раннера GitHub по jitconfig.
- Готовые образы `/Volumes/Dev/vm/images/macos-27-vanilla` и `macos-27-xcode-27.2`, собранные руками.
- `simstream` (D) собирается на хосте, в гость копируется бинарник. Скрипт `simstream/scripts/run-in-guest.sh`
  показывает нюансы: бинарник нельзя перезаписывать на месте, симулятор берётся из `~/udid`.

## Что сделать

1. **Служба гостя `maccheri-guestd`** (Swift, `guest/`):
   - LaunchAgent пользователя `admin` в графической сессии: симулятору нужна она, а автологин в образе уже есть;
   - ждёт `GuestAPI.sharePath/session.json` (проверяет раз в 0,5 с, файл может появиться после загрузки);
   - `ci` — запускает раннер с jitconfig, после его завершения выключает систему;
   - `simulator` — загружает устройство (заранее созданное в образе под нужный `DeviceSpec`),
     запускает `simstream` на `simstreamPort`, держит его, а когда сессия заканчивается
     (simstream вышел или пропала общая папка), выключает систему;
   - логи — в unified log и в файл.
2. **Сборка образа одной командой** (`images/build.sh` или Swift-утилита, на твой выбор):
   - vanilla → клон → диск 90 ГБ → Xcode и рантайм с хоста → GitHub actions-runner (osx-arm64) → `maccheri-guestd`
     и `simstream` → заранее созданные устройства → настройки гостя (выключить Spotlight, обновления, сон,
     заставку) → выключение → каталог образа с `maccheri.json` (`labels`, `devices`, `guestVersion`, см. контракты);
   - имя с версией, например `macos-27-xcode-27.2-v1`; старые образы не удалять;
   - сократить разогрев: прогнать симулятор один раз при сборке, чтобы первый запуск в сессии не был холодным.
     Учти замеченную чёрную заставку при холодном старте приложений (`simstream/README.md`).
3. **Сквозной CI:**
   - вместе с пользователем зарегистрировать GitHub App (manifest flow или руками по инструкции):
     права, вебхук `workflow_job` на URL B, приватный ключ — пользователю, не в репозиторий;
   - тестовый репозиторий с workflow `runs-on: [self-hosted, maccheri]`: `xcodebuild` простого проекта
     и `xcrun simctl` smoke-тест;
   - прогон: push → вебхук → B → агент A → VM → раннер → зелёная галочка → VM удалена;
   - пока B и A не готовы, проверяй службу гостя напрямую: руками положи `session.json`
     в общую папку `maccheri-vm` и смотри, что делает гость.
4. **Документация:** обнови `images/README.md` (как собрать и обновить образ) и `guest/README.md`.

## Готово, когда

- `images/build.sh` из vanilla-образа без ручных шагов собирает образ, который проходит оба сценария:
  - `session.json` с `ci` — раннер выполняет задание;
  - с `simulator` — `simstream` принимает соединения меньше чем через 30 с после записи файла
    в прогретую VM.
- Хотя бы один настоящий workflow на GitHub выполнился в нашей VM через A и B.
