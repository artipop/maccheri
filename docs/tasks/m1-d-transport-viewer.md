# M1 / D: P2P-транспорт, simstream и веб-клиент

Сначала прочитай `docs/contracts.md` (общие правила, владельцы папок, блокировка VM) и `docs/roadmap.md`.
Твои папки: `simstream/`, `web/`, `viewer/`, `protocol/Sources/SimStreamProtocol/`. Worktree: `../maccheri-d`,
ветка `task/transport`.

## Цель

Удалённый симулятор через интернет **в браузере**. Многие клиенты работают на Linux и Windows,
поэтому основной клиент — веб-приложение на TypeScript, без установки. Браузер и мак владельца
соединяются напрямую по стандартному WebRTC. Через наш сервер идут только сигнализация и, если
пробиться не удалось, TURN. Mac Viewer (SwiftUI) остаётся инструментом разработки и замеров.

## Что есть

- `simstream` (сервер в госте, TCP :7300, H.264 через VideoToolbox), `SimStreamClient`, `simstream-bench`,
  Mac Viewer. Задержка клик → кадр в локальной сети 22–26 мс p50 (`bench/simstream/RESULTS.md`,
  `simstream/README.md`). Из них ~7 мс симулятор, ~2 мс масштабирование и NV12, ~6,5 мс кодирование,
  ~3 мс сеть и декодирование.
- Сервер на Swift остаётся. Меняется только путь от мака до браузера.

## Что сделать

1. **Схема WebRTC (замер, потом решение).** Требование: стандартный WebRTC, который понимает
   браузер без плагинов. Цель — минимальная задержка клик → кадр в браузере.
   - **Где пир на стороне мака.** Рекомендация — на хосте, в библиотеке `HostPeer`, которую вызывает
     агент A. Пир соединяется с simstream в госте по TCP. На хосте учётные данные TURN и нет двойного
     NAT vmnet.
   - **Как везти видео**, сравни в Chrome, Safari и Firefox:
     - (a) видеодорожка WebRTC с готовым H.264 из simstream без перекодирования (passthrough или
       кодер в стеке WebRTC). В браузере `<video>` с `receiver.jitterBufferTarget = 0`
       (или `playoutDelayHint`);
     - (b) кадры SimStream через RTCDataChannel (ненадёжный неупорядоченный для видео, надёжный
       для касаний), в браузере WebCodecs `VideoDecoder` (`optimizeForLatency: true`) и отрисовка
       в `<canvas>`. Совсем без джиттер-буфера, но потери и восстановление по ключевым кадрам на нас.
   - Проверь сеть с потерями и задержкой (Network Link Conditioner или `dnctl`/`pfctl` на хосте):
     1–3% потерь, RTT 50 мс.
   - Библиотека WebRTC на стороне мака (Swift): Google WebRTC xcframework через SwiftPM или аналог.
     Скачать можно, это мелкая зависимость.
   - Итог с цифрами по браузерам запиши в `simstream/README.md` и `bench/simstream/RESULTS.md`.
2. **`HostPeer` по контракту** (`docs/contracts.md`, стык A ↔ D):
   - сигнализация B с ролью host (`SignalingInfo.url` уже с токеном), offer, `iceServers`;
   - поток от гостя через `connectToGuest`;
   - выход по bye, отключению или таймауту.

   Пока A не готов, проверяй через свой тестовый CLI, который сам поднимает `HostPeer`.
3. **Веб-клиент `web/`:**
   - TypeScript, минимум зависимостей: Vite плюс ванильный TS или Preact. Сборка в статические файлы
     `web/dist`, их раздаёт B с корня домена (контракт B ↔ D);
   - типы API в `web/src/api.ts` по `MaccheriProtocol`, сверка с JSON-фикстурами B;
   - вход по инвайту, токен пользователя в `localStorage`;
   - список хостов и устройств (`GET /v1/hosts`), «Новая сессия», ожидание `ready`;
   - сигнализация с ролью viewer, WebRTC, экран устройства с сохранением пропорций;
   - мышь и тач (Pointer Events) → касания began, moved, ended;
   - оверлей: тип соединения (прямое или relay, через `getStats`), RTT, fps, Мбит/с,
     задержка клик → кадр (тот же `inputAck`);
   - «Завершить» (DELETE и bye), корректное поведение при закрытии вкладки;
   - режим разработки: подключение к локальному control plane.
   Через пару лет клиент должно быть легко встроить в webview VS Code, так что держи его
   самодостаточным: один `index.html` плюс бандл, без серверного рендеринга.
4. **Возможности устройства** (сервер simstream и веб-клиент):
   - клавиатура: события браузера → Indigo keyboard, см. экспорт `IndigoHIDMessageForKeyboardArbitrary`
     и `…KeyboardNSEvent` в SimulatorKit;
   - кнопка Home или свайп Home, блокировка экрана;
   - поворот экрана;
   - установка своего `.app` (zip): перетаскивание в окно браузера → передача по каналу данных
     → `simctl install` и запуск.
5. **Mac Viewer** оставь рабочим для замеров (режим прямого `host:port`). Переводить его на WebRTC
   не обязательно.
6. Тесты: Swift — протокол, `HostPeer` с фейковой сигнализацией, `LatencyTracker`; веб — юнит-тесты
   на разбор и сборку сообщений и на типы API (vitest).

## Готово, когда

- На компьютере в другой сети (хотспот телефона) — в идеале Linux или Windows, иначе второй мак —
  в Chrome открывается веб-клиент, вход по инвайту, создание сессии и работа с симулятором через
  сервер B. Сначала можно на локальном control plane плюс тестовый CLI вместо агента, потом
  с настоящим A.
- Работает в актуальных Chrome, Safari и Firefox. Задержка клик → кадр и тип соединения видны
  в оверлее, цифры записаны в `bench/simstream/RESULTS.md`.
- Клавиатура, Home, поворот и установка `.app` работают.

## Не делать

Расширение VS Code, нативные обёртки (Tauri и подобные), звук, мультитач, подпись и нотаризацию.
